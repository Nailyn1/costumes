# T-028 · Учёт долга/переплаты при выдаче

- **Приоритет:** medium — желательно до сезона
- **Область:** Баги домена (подтверждены владельцем, см. domain.md §6)
- **Создана:** 2026-10-15

## Контекст

При выдаче `visitIssue` получает фактическую `additionalPayment`, но раскладывает её по заказам не больше остатка каждого. Если денег меньше, долг нигде явно не показан при возврате. Если денег больше, излишек после раскладки теряется. `Order.finalPayment` фиксирует распределённую часть, а не фактически принятую сумму визита. В локальной восстановленной БД 446 выданных/возвращённых визитов выглядят полностью оплаченными; восстановить ранее потерянные излишки из этих полей нельзя.

Решение владельца: при возврате можно принять и зафиксировать оплату долга; переплата — сумма, которую следует вернуть клиенту, а не кредит для будущих визитов. Костюмы можно вернуть и завершить визит при незакрытом денежном балансе — остаток должен оставаться видимым. При отмене ошибочной выдачи доплата, записанная при этой выдаче, отменяется вместе с ней.

## Критерии готовности

- [ ] Фактически принятые деньги сохраняются без ограничения остатком заказа; недоплата и переплата вычисляются по суммам визита и не теряются.
- [ ] Долг/переплата показываются сотруднику при возврате; визит можно выдать с нулевой/частичной доплатой.
- [ ] При возврате можно записать оплату долга и возврат переплаты отдельно от залога; баланс пересчитывается после каждого действия.
- [ ] Возврат костюмов и завершение визита не блокируются долгом или невозвращённой переплатой; баланс остаётся доступен после завершения.
- [ ] Отмена выдачи не оставляет активной финансовой записи для отменённой операции и сохраняет историю действий.
- [ ] Старые визиты без новой записи читаются корректно; миграция совместима с данными прошлого сезона.
- [ ] Новые правила покрыты unit, integration и frontend тестами; API-контракт и `.agents/domain.md` обновлены.

Суммы положительные, направление операции явное; залог остаётся отдельной сущностью. Запись ошибочной выдачи помечается отменённой, история сохраняется. Новая миграция — в `apps/backend/prisma/schema.prisma` и `prisma/migrations/`.
2. Вынести формулу в чистый доменный модуль `apps/backend/src/visit-order/domain/visit-balance.ts`: `баланс = аренда − предоплата − активные поступления + активные возвраты`; положительное значение — долг, отрицательное — сумма к возврату. Для старых визитов учесть `Order.finalPayment` однократным переносом в новую модель либо проверенным совместимым чтением; потерянные старые переплаты восстановить невозможно.
