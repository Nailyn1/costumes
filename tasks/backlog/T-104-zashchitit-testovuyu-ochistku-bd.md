# T-104 · Защитить тестовую очистку БД проверкой фактического подключения

- **Приоритет:** высокий
- **Область:** Тестовая инфраструктура
- **Создана:** 2026-10-23

## Контекст

При расследовании пустой локальной `costumes_backup_20260706` обнаружено: `test/support/test-app.ts:resetDatabase` выполняет TRUNCATE всех публичных таблиц, кроме `_prisma_migrations`, без проверки фактического имени БД. Защита в подготовке окружения не защищает прямой вызов helper из отдельного скрипта. Это найденный риск; его связь с произошедшей очисткой пока не доказана.

По просьбе владельца дамп от 2026-07-06 восстановлен, применены текущие миграции. Прежняя пустая БД сохранена локально как `costumes_before_restore_20261023`. Восстановленная БД использует прежнее имя подключения. После восстановления: 453 клиента, 557 детей, 519 костюмов, 487 визитов, 559 заказов.

## Критерии готовности

- [ ] Непосредственно перед очисткой проверяется фактическая БД через подключение Prisma; разрешён только явно тестовый target с суффиксом `_test`.
- [ ] При несовпадении фактической БД с ожидаемой тестовой операцией очистка запрещена до первого изменения.
- [ ] Прямой вызов helper вне Jest тоже защищён; ошибка не раскрывает пароль или URL подключения.
- [ ] Тесты доказывают отказ для dev/backup БД без TRUNCATE и разрешение для согласованной тестовой БД.
- [ ] Аналогичная очистка Redis проверяет выделенную тестовую логическую БД перед FLUSHDB.

## Результат

Риск записан при восстановлении данных. Защита и установление причины прежней очистки требуют отдельной работы; изменения тестовой инфраструктуры сейчас не выполнялись.
