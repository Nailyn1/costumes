# T-032 · Каталог костюмов: категории, размер, состав и фото (эпик)

- **Приоритет:** high
- **Область:** Фичи
- **Создана:** 2026-10-15
- **Разобрана с владельцем:** 2026-10-25

## Контекст

Сейчас костюм — это только название (`Costume.name`), куда сотрудники на скорую руку пишут всё сразу: «Кавказский дев. 104-116». Найти, например, все кавказские костюмы невозможно; на выдаче не видно, как выглядит костюм и что положить в пакет; на возврате нечем сверить комплектность; при подготовке бирок трудно вспомнить, какой костюм имелся в виду.

Цели владельца: поиск, каталог и статистика по костюмам; фото костюма, снятые быстро с телефона; состав (аксессуары и части) для сборки при выдаче и сверки при возврате.

## Решения владельца (2026-10-25)

**Категории**
- У костюма **одна** категория. Двухуровневый справочник: основная категория → подкатегория.
- Стартовый набор (добавляется миграцией данных, дальше редактируется в интерфейсе):
  - **Национальные:** Кавказские, Татарские, Немецкие, Русские, Белорусские, Украинские, Казахские;
  - **Новогодние:** Супергерои, Классические (принцы, мушкетёры, принцессы), Животные, Снеговики.
- **Пол** — отдельное поле, не категория: Девочка / Мальчик / Унисекс.
- **Размер**: рост в сантиметрах диапазоном (как сейчас пишут «дев. 104-116») и/или размер с бирки костюма («Р32», «Р36»).
- ~500 существующих костюмов **не заполнять** — новые поля необязательные; заполняются по ходу работы.

**Состав (комплектность)**
- Указываем **только то, что можно потерять или забыть положить**: головной убор, накидка, повязка, фартук, саукеле, пояс и т.п. Основу (платье, штаны, рубашку) не пишем.
- «Головной убор» при создании подставляется по умолчанию (снимается одним нажатием), остальное — быстрыми чипсами или своим текстом.
- **Выдача:** состав — только подсказка «Положить в пакет: …», **без чекбоксов**.
- **Возврат:** все части **отмечены по умолчанию**; если чего-то нет — сотрудник снимает галочку. Возврат не блокируется, денег не начисляется; в истории визита появляется запись «Вернули без: …» (обычно клиент довозит часть позже).

**Фото**
- Несколько фото на костюм. С телефона — **непрерывная съёмка**: камера открывается один раз, каждое нажатие сразу делает кадр и ставит его в загрузку, без повторного открытия камеры. Запасной путь — выбор нескольких фото из галереи.
- Хранилище — S3 PS Cloud, как в проекте secmarket (`C:\JavaScript\secmarket\apps\api\src\infrastructure\s3`): публичный бакет, `Cache-Control: immutable`, **загрузка через бэкенд** (прямую загрузку с фронта защита провайдера не пропускала).
- Фото видны на выдаче сразу; на странице незаписанных бирок — по запросу (кнопка).
- Оптимизация долгих сессий без перезагрузки: в списках только превью, большие фото — по открытию.

## Архитектурные решения

| Что | Как хранить | Почему |
|---|---|---|
| Категории | таблица `CostumeCategory` (`name`, `parentId`, `sortOrder`, `deletedAt`), у костюма `categoryId?` | справочник с иерархией, переименование без правки костюмов, фильтр по основной категории включает подкатегории |
| Пол | enum `CostumeGender` (`girl`, `boy`, `unisex`), `Costume.gender?` | отдельный фильтр |
| Размер | `Costume.heightFrom?`, `heightTo?` (см), `sizeLabel?` (`Р32`) | поиск по росту ребёнка, бирка как есть |
| Состав | `Costume.parts Json` — `[{ name, qty }]`, Zod-схема из shared | короткий список, всегда читается и меняется целиком |
| Что выдали | снимок `Order.issuedParts Json` при выдаче | состав костюма потом могут изменить — сверяем с выданным |
| Чего не вернули | событие `AuditEvent` визита с перечнем частей | владелец решил: только пометка в истории |
| Фото | таблица `CostumePhoto` (`costumeId`, `key`, `thumbKey`, `width`, `height`, `sortOrder`, `deletedAt`) | порядок, обложка (первое), soft delete, очистка S3 |

Фото сжимает браузер (~1600 px ~250 КБ и превью ~320 px ~15 КБ), бэкенд получает оба файла одним `multipart` и кладёт в S3 по ключам `costumes/{costumeId}/{uuid}.jpg|_thumb.jpg`.

- [ ] Все подзадачи T-109…T-114 в `tasks/done/` (T-115 — по решению владельца).
- [ ] `.agents/domain.md` описывает категории, пол, размер, состав, фото и их поведение на выдаче/возврате; `architecture.md` — S3 и env.
- [ ] Сквозной сценарий проверен на телефоне: бронь с новым костюмом и серией фото → бирки (просмотр фото) → выдача (фото + «положить в пакет») → возврат с одной снятой частью → запись в истории.
