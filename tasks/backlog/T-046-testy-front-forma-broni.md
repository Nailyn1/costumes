## Критерии готовности

- [ ] Чистые функции (выносить отдельными `refactor(front)`-коммитами без изменения поведения): итоги и остаток (есть: `calcOrderTotals`), «Внесено > аренды → предоплата ограничивается» (логика из `OrderBlock`), умный ввод даты `11` → `11.MM` (`SmartDateInput`), авто-дата возврата = выдача + 1 день и сброс заказов при смене дат (`VisitSelector`/`CreateBookingPage`), формирование payload `createVisit`.
- [ ] Дефолтное время по дню недели (будни 18:30–19:30 / вернуть до 18:00, выходные 10:00–19:00) — **в коде не реализовано** (см. T-050); после T-050 покрыть тестом, до этого — `it.todo`.
- [ ] Клиент: поиск ≥ 2 символов с debounce, клиент из ЧС недоступен (есть), inline-создание с маской телефона и автоселект созданного.
- [ ] Заказ: ребёнок из детей клиента или inline-создание; костюм — поиск с учётом дат визита, занятый помечен; «+ Добавить ещё одного ребёнка» только при заполненных финансах; удаление заказа (кроме первого).
- [ ] Валидация формы: обязательные поля с русскими сообщениями, `prepayment ≤ rent`, дата возврата не раньше выдачи, «Забрать до» позже «Забрать с».
- [ ] Сценарий «Проверить → превью → Подтвердить» с MSW: `POST /visits/preview-code` резервирует код, модалка показывает код/даты/суммы/остаток, чекбокс «Отправить WhatsApp» определяет `?sendNotification=`, после успеха форма сбрасывается; ошибка 409/400 показывается один раз (глобальный toast), форма не сбрасывается.
- [ ] `pnpm test` зелёные, typecheck и lint без новых ошибок.
