# T-097 · Общий журнал действий CRM и история справочников

- **Приоритет:** на согласование владельцем
- **Область:** Фичи
- **Создана:** 2026-10-22

## Контекст

После истории визита может понадобиться узнать, кто создал/изменил клиента, ребёнка или костюм. Общий журнал отвечает на вопрос «что делал сотрудник», карточка визита — «что происходило с этой арендой». Один механизм AuditEvent, два представления.

[Исследование](../research/2026-10-22-visits-quick-issue-history.md), §§1, 6, 8. Зависимость: T-094. Можно отложить, это не блокер быстрой выдачи.

## Критерии готовности

- [ ] События создания/изменения/soft-delete клиентов, детей, костюмов и изменения ЧС в транзакции соответствующего действия.
- [ ] Общий API и экран с фильтрами периода, сотрудника, сущности, действия, серверной пагинацией и ссылками на доступные карточки.
- [ ] Используется AuditEvent T-094, нет второй таблицы истории и копий событий.
- [ ] Старые snapshot-имена сохраняются; удаление сущности не стирает события; старые авторы не выдумываются.
- [ ] Чувствительные поля ограничены явным allowlist; общий журнал не показывает токены/пароли/полные тела запросов.
- [ ] События справочника не показываются во всех визитах клиента; связь с визитом только для действий над самим визитом/заказом.
- [ ] Тесты авторства, rollback и фильтров, десктоп/375px, DoD.

## План

1. Утвердить список событий и показываемых полей; новые actions/DTO через shared.
2. Встроить вызовы сервиса событий в client-child/costumes без универсального аудита всех HTTP-запросов.
3. Read API общего журнала и UI, понятные ссылки на удалённые сущности без ошибочной навигации.
4. Проверить фильтры/объём, задокументировать начало накопления истории.
