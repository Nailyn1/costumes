# T-092 · Явные доменные правила визита

- **Приоритет:** medium — после T-028
- **Область:** Архитектура backend
- **Создана:** 2026-10-20

## Контекст

Бизнес-правила бронирования, выдачи, отмены и возврата сосредоточены в `apps/backend/src/visit-order/visit-order.service.ts` (около 1400 строк) вместе с запросами Prisma и формированием API-ответов. Из-за этого границы правил трудно увидеть и тестировать отдельно. Записи Prisma являются состоянием хранения, а не доменными объектами; оборачивать каждый Client/Costume/Visit/Order в класс без поведения не даст пользы.

Первый кандидат на явную границу — визит как единая операция над заказами, платежами и залогом. Финансовую модель T-028 сначала стабилизировать, чтобы не переписывать её дважды.

## Критерии готовности

- [ ] Чистые доменные правила визита живут в `apps/backend/src/visit-order/domain/`, не импортируют NestJS, Prisma, HTTP DTO или UI.
- [ ] Правила переходов `reserved → issued → completed`, отмены выдачи, расчётов и проверки всех заказов представлены методами/функциями с явными входами и результатами.
- [ ] `VisitOrderService` остаётся координатором загрузки, транзакций, сохранения и перевода доменных ошибок в HTTP-ошибки.
- [ ] Поведение API и схема БД не меняются только ради рефакторинга; существующие integration-сценарии остаются зелёными.
- [ ] Новые unit-тесты покрывают доменные правила напрямую, а не повторяют устройство класса.
- [ ] Решение о следующей границе (Client, Costume или Notification) принято по обнаруженному дублированию логики, а не по требованию «все сущности должны стать классами».

## План и файлы

1. После T-028 выделить карту инвариантов из `apps/backend/src/visit-order/visit-order.service.ts` и связанных тестов.
2. Создать `apps/backend/src/visit-order/domain/visit.ts` (или набор чистых функций, если класс не даёт выигрыша), `visit-balance.ts` из T-028 и доменные ошибки/типы в той же папке. Не переносить Prisma-модели в домен напрямую.
3. Оставить загрузку связей, транзакции и запись в `visit-order.service.ts`; постепенно заменить встроенные расчёты и проверки вызовами доменных правил.
4. Обновить `apps/backend/src/visit-order/visit-order.service.spec.ts`, добавить тесты `domain/*.spec.ts`, прогнать `apps/backend/test/visit-flow.int-spec.ts` и весь `pnpm test:int`.
5. Зафиксировать выбранные границы в `.agents/backend.md` и `.agents/domain.md`. Следующие сущности выносить отдельными небольшими задачами.
