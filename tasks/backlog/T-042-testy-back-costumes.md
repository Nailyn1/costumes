## Критерии готовности

- [ ] Создание/обновление/удаление: `inventoryCode` генерируется БД (`C-NNNN`, integration), удаление — soft delete (`deletedAt`), удалённый костюм не находится ни поиском, ни по id, ни среди доступных.
- [ ] `search`: поиск по названию и `inventoryCode` (регистр, пробелы, минимум 2 символа), ранжирование точное > префикс > с начала слова.
- [ ] `search-available`: учитывает даты визита — костюм с пересекающимся не отменённым заказом помечается занятым, встык — свободен; отменённые/удалённые заказы не блокируют; возвращённые блокируют (T-024, `it.todo`).
- [ ] `availability` (`:costumeId/availability`): периоды занятости отсортированы по дате начала, содержат ребёнка, visitCode, телефон, даты; пустой список — без ошибок; без сумм и залогов.
- [ ] `list`: пагинация, сортировка, исключение удалённых.
- [ ] Тест фиксирует, что занятость считается по заказам, а не по `Costume.status` (domain.md §6.1; T-025).
- [ ] `pnpm test` и `pnpm test:int` зелёные, typecheck и lint без новых ошибок.
