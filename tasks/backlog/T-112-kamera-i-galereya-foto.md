## Контекст

Выдача и бронь часто идут с телефона. Владелец хочет: камера открывается один раз, каждое нажатие сразу делает фото и отправляет его в загрузку — без повторного открытия камеры на каждый кадр (так работает обычный `<input capture>`, это не подходит). Сотрудники долго работают без перезагрузки страницы — фото не должны забивать память.

## Что сделать (переиспользуемые компоненты в `features/costumes/photos/`)

1. **`CostumeCamera`** — полноэкранная модалка с `getUserMedia({ video: { facingMode: "environment" } })`: видоискатель, кнопка затвора, лента снятых кадров с удалением тапом, счётчик загрузки «↑ 2/5», «Готово». Кадр: `video` → `canvas` → сжатие. Поток камеры останавливается при закрытии/размонтировании. Нет доступа к камере / нет HTTPS → понятное сообщение и переход к выбору из галереи.
2. **Запасной путь** — `FileButton` с `accept="image/*" multiple` (выбор нескольких фото из галереи/с ПК).
3. **Сжатие** (`utils/compressImage.ts`, чистая функция + тест): длинная сторона 1600 px JPEG ~0.82 (`image`) и 320 px (`thumb`); учитывать EXIF-ориентацию (`createImageBitmap(..., { imageOrientation: "from-image" })`); исходный файл после сжатия не держать.
4. **Очередь загрузки** (`hooks/usePhotoUploadQueue`): параллельность 2, повтор при сетевой ошибке, статус каждого кадра; режим «костюм ещё не создан» — сжатые кадры ждут в памяти и уходят после появления `costumeId` (для формы создания в брони/быстрой выдаче); инвалидация фото и `coverThumbUrl` костюма после загрузки.
5. **`CostumePhotoStrip`** — горизонтальная лента превью (Mantine `ScrollArea`, листается пальцем), `loading="lazy"`, фиксированный размер; пустое состояние — кнопка «📷 Добавить фото».
6. **`CostumePhotoViewer`** — просмотр в модалке: полный размер грузится только при открытии, стрелки/свайп, счётчик «3/7», на мобиле fullScreen.
7. **Память и кэш**: в React Query — только метаданные и URL; `URL.createObjectURL` превью кадров освобождать сразу после загрузки/удаления; большие изображения в DOM только внутри открытого просмотрщика; список фото костюма загружается по требованию (`enabled`), `gcTime` по умолчанию.

Встраивание компонентов в формы и экраны — T-113 и T-114.

## Критерии готовности

- [ ] На телефоне (HTTPS) серия из 5+ кадров снимается без повторного открытия камеры и загружается в фоне; на ПК работает выбор нескольких файлов.
- [ ] Сжатие: фото с телефона ≤ ~400 КБ, превью ≤ ~30 КБ, ориентация правильная.
- [ ] Vitest: сжатие (размеры), очередь (параллельность, повтор, ожидание `costumeId`), лента и просмотрщик (MSW).
- [ ] Ручная проверка: 20+ минут работы с открытием/закрытием камеры и просмотром фото без роста памяти вкладки (DevTools → Memory) — описать результат.
- [ ] `.agents/frontend.md`: раздел про фото (компоненты, правила памяти, HTTPS для камеры, как тестировать с телефона).
