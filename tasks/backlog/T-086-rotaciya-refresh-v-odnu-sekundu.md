# T-086 · Ротация refresh-токена при быстром повторном выпуске

- **Приоритет:** high
- **Область:** Баги домена
- **Создана:** 2026-10-18

## Контекст

`AuthService.issueTokens` подписывает refresh JWT только с payload `{id, login}` и фиксированным сроком `7d`. Два выпуска в течение одной секунды дают побайтно одинаковый JWT (подтверждено через `JwtService.sign`), потому что `iat` имеет секундную точность. При `POST /auth/refresh` новый токен тогда совпадает со старым, а ротация не отзывает старый cookie.

## Критерии готовности

- [ ] Каждый успешный refresh выпускает новый, отличный от старого токен даже в ту же секунду.
- [ ] Сразу после refresh старый cookie возвращает 401, новый работает.
- [ ] Redis-ключ `rf:{userId}` сохраняет только актуальный токен с TTL 7 дней.
- [ ] Unit и integration тесты доказывают ротацию без задержек по времени.
