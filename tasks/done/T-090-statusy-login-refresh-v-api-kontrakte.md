# T-090 · Исправить HTTP-статусы login и refresh в API-контракте

- **Приоритет:** high
- **Область:** Баги домена
- **Создана:** 2026-10-20
- **Выполнена:** 2026-10-20

## Контекст

После перехода на typed-openapi успешный `POST /auth/login` возвращал HTTP 201, но TypeSpec описывал 200. Клиент применял схему `Common.Error` к успешному телу и показывал `Operation error` вместо входа. У `POST /auth/refresh` было такое же расхождение.

## Критерии готовности

- [x] TypeSpec описывает фактический успешный статус 201 для login и refresh; клиент перегенерирован.
- [x] Тесты клиента принимают ответы Nest без видимого браузеру `Set-Cookie`.
- [x] Моки refresh используют фактический статус; тесты авторизации и общие проверки проходят.

## План

Исправить контракт, перегенерировать `shared`, добавить регрессионный тест и проверить авторизацию, typecheck и lint.

## Результат

Статусы двух операций исправлены в TypeSpec и generated-клиенте. Добавлен регрессионный тест для login/refresh с HTTP 201; MSW-моки refresh приведены к фактическому ответу Nest. Проверки: `shared` build, backend typecheck, frontend build и lint, `pnpm test` (backend 262, frontend 125), профильные тесты API-клиента и interceptors (26) прошли. Коммит не создавался.
