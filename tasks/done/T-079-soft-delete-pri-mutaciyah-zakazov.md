# T-079 · Soft delete при изменении заказов визита

- **Приоритет:** medium
- **Область:** Баги домена
- **Создана:** 2026-10-18
- **Выполнена:** 2026-10-18

## Контекст

При аудите T-077 найдены мутации в `apps/backend/src/visit-order/visit-order.sevice.ts`, которые читают или обновляют заказы визита без фильтра `deletedAt: null`: `visitIssue`, `visitUnissue`, `visitCompleteReturn`, `visitCancel`. `orderMarkTagWritten` обновляет заказ по ID без проверки soft delete. Эти методы не входили в T-077, посвящённую читающим выборкам.

## Критерии готовности

- [x] `visitIssue` читает только активные заказы и выдаёт только их; обновление каждой строки также ограничено `deletedAt: null`.
- [x] `visitUnissue`, `visitCompleteReturn` и `visitCancel` обновляют только активные заказы.
- [x] `orderMarkTagWritten` проверяет `deletedAt: null` и возвращает 404 с русским сообщением для удалённого заказа.
- [x] Регрессионные unit-тесты проверяют фильтры чтения/обновления и 404 для удалённой бирки.
- [x] Backend unit, typecheck и lint проходят. Общий integration-набор проходит; отдельный сценарий T-079 не добавлялся, условия soft delete проверены на уровне сервиса.

## План

1. Добавить красные unit-тесты для `visitIssue`, `visitUnissue`, `visitCompleteReturn`, `visitCancel` и `orderMarkTagWritten` с soft-deleted orders.
2. Добавить `deletedAt: null` во вложенные выборки и условия обновлений; одиночное обновление бирки выполнять с условием активной записи и возвращать 404 для отсутствующей записи.
3. Запустить unit suite, typecheck и lint изменённых файлов; integration не запускать из-за общей тестовой БД/Redis.

## Результат

Добавлены фильтры `deletedAt: null` во вложенные выборки выдачи и возврата, в точечное обновление каждого заказа при выдаче и в массовые обновления возврата, отмены и снятия выдачи. Обновление бирки также ограничено активной записью и для удалённого заказа возвращает 404 «Заказ с ID … не найден».

Регрессионные unit-тесты сначала падали на старых запросах, затем прошли после исправления. Проверки всего рабочего дерева: backend unit — 11 suites / 206 passed / 7 todo; integration — 4 suites / 18 passed; typecheck и полный backend lint прошли.
