# T-106 · Компактный список визитов и модальная карточка

- **Создана:** 2026-10-25
- **Область:** Frontend
- **Статус:** выполнена по коду 2026-10-25; ручная приёмка владельцем

## План

1. Сверху поиск, ниже горизонтальные статусы «Все / Бронь / Выдан / Возвращён / Отменён» на Mantine. Период по умолчанию «За всё время», по нажатию отдельный фильтр. Сегодня/вчера/с начала недели (понедельник)/произвольный период. Владелец подтвердил: по дате выдачи. Desktop — фильтр под иконкой; mobile-компоненты в отдельной папке mobile.
2. Список сохраняет пагинацию, поиск и ошибки. Вся строка таблицы и мобильная карточка открывают модалку, с клавиатуры тоже. Отдельную кнопку «Карточка» убрать. Прямая ссылка на визит остаётся рабочей и открывает модалку поверх списка.
3. Карточка: имя клиента + номер визита + меню действий, телефон, значок/тип/состояние залога. Компактный период через слеш, окно выдачи, возврат до. Суммы в одной группе: аренда, предоплата, доплаты, всего получено; возврат клиенту/долг/к возврату только при >0.
4. Состав: костюм, inventoryCode, статус, ребёнок, аренда/предоплата/историческая доплата заказа; не дублировать даты. Не приписывать Order.finalPayment точность фактического платежа: финансовый баланс считается по журналу.
5. Объединить историю и деньги в одну хронологию: короткие события, сотрудник и время. Имена детей/костюмов показывать для бирок; денежные события одной команды не дублировать. Предоплата на создании — сумма из snapshot создания. Доплаты/залоги на выдаче и расчёты при возврате — из событий команды. Старые операции без аудита показать отдельно внутри той же истории без выдуманных автора и времени; импортированные операции без фактической даты.
6. Устранить мерцание inline-создания ребёнка внутри модалки дополнительной выдачи, подтвердить причину тестом. Сохранить черновик/версию и защиту повторов.

Связанная доработка: [T-107](T-107-predoplata-novogo-zakaza-v-redaktore.md).
