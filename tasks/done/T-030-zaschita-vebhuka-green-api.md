## Контекст

`POST /webhooks/whatsapp` был открыт без проверки: любой мог подделать статус доставки, «подтверждение клиента» или состояние инстанса. Green-API умеет слать заголовок `Authorization: Bearer <webhookUrlToken>` (настройка инстанса).

## Критерии готовности

- [x] Сравнение в постоянное время (SHA-256 обоих значений + `timingSafeEqual`)

- [x] `.env.example` (корень, backend, `.env.test.example`), `.agents/setup.md` §2, `.agents/domain.md` §5, `.agents/backend.md`

## Результат

`WebhookTokenGuard` (`apps/backend/src/notification/webhook-token.guard.ts`) навешен на `handleWebHook`. Решение для незаданного токена: в `production` вебхук отклоняется (и пишется error в лог), в dev/test — пропускается с warning, чтобы локальная работа и integration-тесты не требовали настройки.

**Владельцу:** сгенерировать длинную случайную строку, записать в `.env` сервера как `GREEN_API_WEBHOOK_TOKEN` и ту же строку указать в кабинете Green-API → инстанс → настройки → «Токен вебхука» (`webhookUrlToken`). Порядок важен: пока токен не задан в `.env`, прод-вебхуки будут получать 401. Коммит — в ветке `claude/notifications-security-6b8030`.
