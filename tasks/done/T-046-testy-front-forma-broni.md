- [x] Заказ: ребёнок из детей клиента или inline-создание; костюм — поиск с учётом дат визита, занятый помечен; «+ Добавить ещё одного ребёнка» только при заполненных финансах; удаление заказа (кроме первого).
- [x] Валидация формы: обязательные поля с русскими сообщениями, `prepayment ≤ rent`, дата возврата не раньше выдачи, «Забрать до» позже «Забрать с».

## Результат

Вынесены чистые функции (`features/visits/utils/bookingForm.ts`, отдельный коммит `refactor(front)` без изменения поведения): ограничение предоплаты арендой, умный ввод даты, дата возврата = выдача + 1 день, пустой заказ, payload `createVisit`. Тесты: `bookingForm.test.ts` (12) и `pages/CreateBookingPage.test.tsx` (16 + 4 `it.todo`) — сценарий через MSW от выбора клиента до `POST /visits`: превью (код, даты, суммы, остаток), `sendNotification=true|false`, сброс формы после успеха, ошибка 400 «клиент в чёрном списке» (один toast, форма и превью остаются), обязательные поля, ограничение предоплаты арендой, сброс заказов при смене дат, дата возврата не раньше выдачи, обратный интервал «Забрать с/до», занятый костюм `[ЗАНЯТ]` недоступен, inline-создание клиента с маской телефона.
Расхождения с описанием (не чинились): «Внесено > аренды → поле очищается» в коде — предоплата ограничивается арендой; «Добавить ещё ребёнка» не ждёт финансов — [T-071](T-071-dobavit-rebenka-posle-finansov.md); предоплата 0 не проходит валидацию — [T-072](T-072-predoplata-nol-obyazatelna.md); контракт `preview-code` расходится с бэкендом — [T-070](T-070-kontrakt-preview-code.md); умное время по дню недели — T-050 (`it.todo` + тест текущего поведения). Критерии «поиск клиента ≥ 2 символов/ЧС» покрыты образцом `clientSearchField.test.tsx` и T-048.
