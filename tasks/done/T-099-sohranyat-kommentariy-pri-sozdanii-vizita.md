# T-099 · Сохранять комментарий при создании визита

- **Приоритет:** на согласование владельцем
- **Область:** Баги домена
- **Создана:** 2026-10-22
- **Выполнена:** 2026-10-22

## Контекст

Обнаружено при исследовании T-036/T-033: `CreateVisitRequest` и `buildCreateVisitPayload` содержат notes, но `visit-order.service.ts:createVisit` не передаёт `data.notes` в `tx.visit.create`. Заметка визита теряется. Это отдельное исправление, не сделано молча в исследовании.

## Критерии готовности

- [x] Тест воспроизводит потерю комментария на старом коде; создание сохраняет notes в БД.
- [x] Без комментария и с пустым комментарием поведение определено существующим контрактом.
- [x] Комментарии заказов не затронуты; DoD.

## План

1. Integration/unit-тест на существующий контракт и БД; минимальная правка createVisit.
2. Проверки и учёт конфликта с T-094/T-036, которые меняют тот же метод.

## Результат

`createVisit` передаёт `data.notes` в `Visit.create`. Unit-тест подтверждённо краснел на старом коде и проверяет независимое сохранение комментария заказа. Integration-тест проверяет сохранение непустой заметки, `null` при её отсутствии и пустую строку.

Проверки: `pnpm test` (backend 313 passed, frontend 143 passed; по одному существующему todo в каждом пакете), `pnpm test:int` (9 suites, 41 passed), backend typecheck, frontend `tsc -b`, shared build и ESLint изменённых файлов прошли. Полный backend lint остаётся с пятью существующими Prettier-ошибками в `redis.idempotency.ts` и `redis.idempotency.spec.ts`.

Коммит: `fix(back): preserve visit notes when creating visits`.
