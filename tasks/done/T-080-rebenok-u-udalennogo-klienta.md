# T-080 · Запретить добавление ребёнка удалённому клиенту

- **Приоритет:** medium
- **Область:** Баги домена
- **Создана:** 2026-10-18
- **Выполнена:** 2026-10-18

## Контекст

`ClientChildService.createChild` проверяет клиента по `id` через `findUnique` без `deletedAt: null`. После мягкого удаления клиента API всё ещё может создать ему ребёнка. См. `apps/backend/src/client-child/client-child.service.ts` и правило soft delete в `.agents/domain.md`.

## Критерии готовности

- [x] Создание ребёнка у удалённого клиента возвращает 404, запись ребёнка не появляется.
- [x] Создание ребёнка у активного клиента продолжает работать.
- [x] Добавлены unit- и интеграционный тесты.

## План

1. Добавить `deletedAt: null` в выборку клиента в `createChild`.
2. Покрыть активного и удалённого клиента unit-тестами и добавить HTTP-сценарий.
3. Запустить unit, typecheck и lint; integration оставить владельцу из-за общей тестовой БД/Redis.

## Результат

Добавлен фильтр активного клиента в `createChild`; удалённый клиент получает русскую 404 до создания ребёнка. Unit-тест подтверждает фильтр и отсутствие вызова `child.create`; существующий тест активного клиента остаётся зелёным. HTTP-проверки в `client-child.int-spec.ts` прошли в общем integration-наборе (28/28).
