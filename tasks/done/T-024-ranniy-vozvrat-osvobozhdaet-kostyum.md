## Контекст

проверка пересечений не должна учитывать `returned` заказы (или учитывать фактическую дату возврата).

- [x] Регрессионный unit-тест подтверждает, что запрос конфликтов выбирает только `reserved`/`issued`, позволяя создать бронь после возврата.
- [x] Добавлен integration-сценарий: заказ выдан и возвращён до плановой даты окончания, затем пересекающаяся бронь того же костюма создаётся с ответом 201.
- [x] Поиск доступности и список периодов костюма не считают `returned` заказ активной бронью; тест `T-024` в `costumes.service.spec.ts` фиксирует оба фильтра.
- [x] Backend unit, typecheck и полный lint проходят.
- [x] Integration-сценарий раннего возврата прошёл на тестовой БД (1 passed); полный integration-набор также прошёл (18 passed).

2. Ограничить конфликтный запрос статусами `reserved` и `issued`, сохранив фильтры удалённых записей и пересечения дат.
3. Заменить `T-024` todo в тестах костюмов регрессионной проверкой поиска и периодов.
4. Добавить integration-сценарий раннего возврата; владелец запускает integration наборы последовательно из-за общей БД/Redis.
