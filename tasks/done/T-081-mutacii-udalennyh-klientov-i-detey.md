# T-081 · Не изменять удалённых клиентов и детей

- **Приоритет:** medium
- **Область:** Баги домена
- **Создана:** 2026-10-18
- **Выполнена:** 2026-10-18

## Контекст

Операции обновления и повторного удаления клиента и ребёнка, а также добавление и снятие клиента с чёрного списка используют `id` без проверки `deletedAt: null` в `ClientChildService`. Удалённую запись можно изменить повторным API-запросом. См. `apps/backend/src/client-child/client-child.service.ts` и правило soft delete в `.agents/domain.md`.

## Критерии готовности

- [x] Изменение, повторное удаление и изменение чёрного списка удалённого клиента возвращают 404 без изменения записи.
- [x] Изменение и повторное удаление удалённого ребёнка возвращают 404 без изменения записи.
- [x] Добавлены unit- и интеграционные тесты.

## План

1. Добавить `deletedAt: null` в update для клиентов/детей и преобразовать отсутствующие записи в русские 404.
2. Добавить unit-тесты на фильтры, ошибки и отсутствие успешных мутаций; покрыть HTTP-сценарием.
3. Запустить unit, typecheck и lint; integration оставить владельцу из-за общей тестовой БД/Redis.

## Результат

`updateClient`, `deleteClient`, `updateChild`, `deleteChild` и оба метода чёрного списка фильтруют `deletedAt: null`; повторное удаление и изменение удалённого ресурса дают русские 404. Добавлены unit-проверки и интеграционный сценарий, который сверяет записи до и после неудачных запросов. Общий integration-набор прошёл (28/28).
