# T-033 · Редактирование визита

- **Приоритет:** не определён — красная карточка canvas, не разобрана с владельцем
- **Область:** Фичи из canvas (красные карточки — ещё не разобраны с владельцем)

## Контекст

Исходная задача охватывала редактирование, карточку и историю. После исследования разделена на независимые результаты: общий список/карточка — T-095, аудит — T-094, добавление с выдачей в issued — T-096. Здесь остаётся редактирование **reserved** визита.

Подтверждено владельцем: при другой дате возврата нужен отдельный визит. Общие клиент и обе даты — условие добавления в существующий.

Исследование: [проект решения](../research/2026-10-22-visits-quick-issue-history.md), §§3, 5, 7–9. Код: `visit-order/domain/visit.ts`, `visit-order.service.ts:isSuitAvailability/createVisit`, `OrderList.tsx`, `VisitSelector.tsx`, `schema.prisma`, `shared/api-spec/modules/visits.tsp`.

Зависимости: T-094, T-095, T-098 выполнены. T-100 и T-101 отложены владельцем и не блокируют редактор. Поиск/запрет совпадающих визитов в эту волну не входит; новых ограничений уникальности не вводить.

## Решения владельца от 2026-10-22

- Первая версия — исправление брони до выдачи (`reserved`). Изменение уже выданных заказов (замена, удаление, цена) пока не берётся в работу; дополнительная выдача выделена в T-096.
- При редактировании сохраняются ID визита и `visitCode`, включая добавление костюма ребёнку. Ранее отправленное WhatsApp-сообщение остаётся прежним; код из него продолжает действовать.
- Редактирование само не отправляет WhatsApp. Кнопка отправки сейчас не нужна; отдельная будущая задача — T-101. Поведение существующей очереди не меняется и остаётся отдельной отложенной задачей T-100.
- При разных датах возврата нужен отдельный визит (ранее подтверждено).
- Итоговый план утверждён: реализация разрешена несколькими агентами в одном дереве с отдельным коммитом на задачу, без push.
- При изменении дат, ребёнка или костюма написанная бирка становится `not_written`; цена и заметки бирку не сбрасывают. Новый заказ — `not_written`.
- Предоплату в первой версии не изменять. Удаление заказа с предоплатой запрещено; замена костюма сохраняет внесённую сумму, новая цена не может быть ниже неё. Отдельный возврат/перенос предоплаты не реализуется.
- Владелец явно исключил из волны поиск/запрет совпадающих визитов и любые изменения существующей очереди WhatsApp. Прежняя очередь остаётся как есть, включая известные ограничения T-100.

## Критерии готовности

- [x] Из карточки reserved можно изменить общий период, добавить заказ, заменить ребёнка/костюм и убрать заказ; существующие orderId сохраняются.
- [x] Существующего клиента менять нельзя в первой версии; дети принадлежат этому клиенту.
- [x] Все активные Orders получают общий период; доступность проверяется заново без конфликта с заменяемыми строками этого же визита.
- [x] Один костюм не дублируется, хотя одному ребёнку разрешены несколько костюмов; все сущности активны, удаление заказа — soft-delete.
- [x] Последний заказ не удаляется: предложена отмена визита; issued/completed/cancelled не принимаются обычным PATCH.
- [x] Реальная предоплата не исчезает и не меняется скрыто; цена ниже неё отклоняется до отдельного согласованного сценария расчёта.
- [x] Удаление заказа с предоплатой запрещено до реализации согласованного возврата/переноса денег; замена костюма в том же Order сохраняет внесённую сумму.
- [x] Устаревшая expectedVersion даёт 409 и сохраняет ввод; изменение и AuditEvent атомарны.
- [x] Написанные бирки инвалидируются по согласованным правилам, с событием; не оставлять физическую бирку заведомо устаревшей.
- [x] WhatsApp не отправляется неявно; существующая очередь и старое сообщение не меняются.
- [x] При смене даты строки формы сохраняются, конфликты доступны сотруднику; состояние клиентского selector корректно гидратируется из detail.
- [x] Unit/integration/frontend-тесты, линтеры и TypeScript-проверки прошли; ручная проверка в браузере и на 375 px ждёт владельца по [чек-листу](../research/2026-10-23-visit-manual-qa.md).
