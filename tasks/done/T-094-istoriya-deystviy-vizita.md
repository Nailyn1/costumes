## Контекст

Сейчас createdAt/updatedAt не отвечают, кто написал бирку, выдал/вернул костюмы, отменил выдачу или вернул залог. Нужен транзакционный журнал событий, общий для будущей истории визита и журнала CRM.

[Исследование](../research/2026-10-22-visits-quick-issue-history.md), §§2, 6, 8–10. UI карточки — T-095, аудит справочников и общий журнал — T-097.

## Критерии готовности

- [x] Добавочная модель AuditEvent: автор из JWT/User, snapshot имени, время, источник, action, entity/visit/order, commandId, версия payload и типизированные данные.
- [x] Событие и изменение сохраняются одной транзакцией; ошибка истории откатывает действие.
- [x] Покрыт существующий цикл: создание, бирка, выдача, отмена выдачи, отмена брони, возврат, возврат залога, денежные операции. Повтор без изменения не создаёт ложное событие.
- [x] События сохраняют нужные старые значения/имена и не переписываются при изменении справочника; нет API изменения/удаления событий.
- [x] `GET /visits/:id/history` защищён auth, пагинирован, имеет стабильный порядок; отменённые визиты доступны, soft-deleted обрабатываются по политике проекта.
- [x] Старые визиты не получают выдуманных событий/авторов; понятна граница начала истории.
- [x] Типы payload/API через shared; источник user/system/import различается; нет полных request bodies, паролей/токенов.
- [x] Проверено время отображения событий отдельно от дат аренды; правило UTC-as-local для аренды сохранено.
- [x] Тесты: автор не подменяется body, rollback, повтор, порядок, переименование справочника, старый визит; общий DoD.

## План

1. Согласовать каталог событий и DTO с T-095; TypeSpec → gen → exports/build.
2. Новая миграция AuditEvent и индексы; без изменения старых таблиц истории/сумм. Prisma migrate dev только по правилам проекта.
3. Небольшой сервис записи событий с переданным tx; типизированный actor context из контроллеров, не универсальный HTTP interceptor.
4. Подключить существующие мутации VisitOrderService, включая markTagWritten, к атомарной записи. Не переписывать модель на Event Sourcing.
5. Read API и тесты; обновить docs. Следующая T-098 меняет тот же сервис последовательно, не параллельно.

## Результат

Реализованы TypeSpec-контракт, типизированные payload-схемы, добавочная Prisma-модель и миграция, транзакционная запись событий для существующих операций и защищённый API истории. Старые визиты без событий возвращают пустой список; история сортируется по `occurredAt, id` по возрастанию. Снимки автора и связанных имён не зависят от последующих изменений справочников.

Миграция `20261022080202_add_visit_audit_events` создана командой `prisma migrate dev` на отдельной migration-БД и содержит только создание таблицы, внешних ключей и индексов.

Проверки: `pnpm test` (backend 319 passed, frontend 154 passed, по одному существующему todo), `pnpm test:int` (10 suites, 46 passed), shared build, backend typecheck, frontend `tsc -b`, ESLint изменённых файлов и `git diff --check` прошли. Полный backend lint имеет прежние пять Prettier-ошибок в `redis.idempotency.ts` и `.spec.ts`; они не менялись. Визуальная проверка интерфейса истории выполняется в T-095, здесь проверены API и транзакционная запись.
