# T-078 · Soft delete в изменении и проверке занятости костюмов

- **Приоритет:** medium
- **Область:** Баги домена
- **Создана:** 2026-10-18
- **Выполнена:** 2026-10-18

## Контекст

При T-042 обнаружено: `CostumesService.updateCostume` и `deleteCostume` используют `where: { id }`, поэтому уже удалённый костюм можно изменить или повторно удалить. `searchCostumeAvailable` не фильтрует `orders.deletedAt` и `visit.deletedAt`, а `costumesAvailability` не исключает удалённый визит из периодов занятости. Это противоречит правилу soft delete в [domain.md](../../.agents/domain.md) §3.

## Критерии готовности

- [x] Изменение и удаление уже удалённого костюма возвращают 404.
- [x] Удалённые заказы и визиты не делают костюм занятым и не показываются в периодах занятости.
- [x] `it.todo` по этим случаям в `costumes.service.spec.ts` заменены регрессионными тестами.
- [x] Тесты и integration зелёные, typecheck и lint без новых ошибок (запущены напрямую из локальных `node_modules`).

## План

- [x] Добавить регрессионные unit-тесты на недоступность update/delete для удалённого костюма и фильтрацию удалённых заказов/визитов.
- [x] Добавить `deletedAt: null` в запросы изменения, удаления и проверки занятости.
- [x] Добавить API/integration-проверки фактической доступности при удалённом заказе и визите; integration оставить владельцу из-за общей БД/Redis.
- [x] Выполнить unit-тест, typecheck и lint backend.

## Результат

`updateCostume` и `deleteCostume` выбирают только активный костюм. `searchCostumeAvailable` и `costumesAvailability` исключают удалённые заказы и визиты. Добавлены unit-проверки Prisma-фильтров и integration-сценарии, которые создают реальные записи и проверяют API-ответы отдельно для удалённого заказа и визита. PATCH/DELETE после удаления костюма проверяются на 404.

Приёмка: backend unit — 179 passed, 3 todo; integration — 9 passed; typecheck и полный backend lint — успешно. API integration проверяет 404 при изменении/повторном удалении удалённого костюма и доступность костюма после удаления заказа или визита.
