# T-089 · Создание тестовой БД при первом запуске integration-тестов

- **Приоритет:** low
- **Область:** Инфраструктура
- **Создана:** 2026-10-20
- **Выполнена:** 2026-10-20

## Контекст

На чистом dev PostgreSQL `pnpm test:int` останавливается на `prisma migrate deploy` с `Schema engine error`, если базы `costumes_test` ещё нет. Скрипт `apps/backend/test/prepare-test-db.ts` и `.agents/testing.md` обещают её автоматическое создание, но `migrate deploy` этого не делает. Сейчас базу приходится предварительно создавать вручную.

## Критерии готовности

- [x] `pnpm test:int` создаёт только БД с именем `*_test`, если она отсутствует, до вызова `prisma migrate deploy`.
- [x] Повторный запуск использует существующую тестовую БД без пересоздания.
- [x] Проверка имени БД и изоляция от dev/прод-БД сохраняются.
- [x] Инструкции в `.agents/testing.md` соответствуют фактическому первому запуску.

## План

Добавить подготовку существования БД перед миграцией, покрыть правила безопасности unit-тестами и уточнить инструкции.

## Результат

Реализовано создание БД через maintenance database `postgres` только для PostgreSQL URL с суффиксом `_test`; существующая БД используется без пересоздания. Обновлены инструкции и `.env.test.example`. Проверено четырьмя unit-тестами и фактическим первым запуском на новой временной `costumes_t089_probe_test`: созданы БД и 21 миграция, повторный запуск не пересоздал БД и не применял миграции. Временная БД удалена после проверки. Backend typecheck и lint прошли; `pnpm test:int` — 34 теста.

Дополнение 2026-10-20: helper `test-database.ts` перенесён из `test/support` в `src/test-utils`. Иначе unit-тест внутри `src` импортировал файл вне `rootDir: src`, и `nest start --watch` падал с TS6059. Пути импорта теста и скрипта подготовки БД обновлены. После исправления прошли backend typecheck, build, lint, 4 unit-теста helper и 35 integration-тестов.
