# T-107 · Предоплата нового заказа в редакторе брони

- **Создана:** 2026-10-25
- **Область:** Shared / Backend / Frontend
- **Статус:** выполнена по коду 2026-10-25; ручная приёмка владельцем

## Правило

Владелец запросил ввод предоплаты при добавлении нового костюма в редакторе reserved-визита. Меняется прежнее ограничение «новый заказ только с нулевой предоплатой». У существующих заказов предоплата остаётся неизменной; изменение денег выданных заказов не входит в задачу.

## План

1. Через TypeSpec добавить optional prepaymentAmount в UpdateReservedVisitOrder, целое >=0. Старые клиенты без поля совместимы, новая строка по умолчанию 0.
2. Для нового заказа проверить <=rentPrice, сохранить предоплату и audit snapshot атомарно с командой/receipt/version. Для существующего — запретить изменение переданного значения; не менять журнал доплат и не дублировать предоплату в VisitMoneyOperation.
3. В UI новый заказ получает редактируемое поле; существующий readonly. Unsaved новую строку можно удалить даже с введённой предоплатой, сохранённый оплаченный заказ удалить нельзя. Восстановление pending-запроса сохраняет новую предоплату.
4. Тесты валидации, сохранения, баланса, истории и повтора; API генерируется и собирается. Интеграционные тесты только в выделенной фактически проверенной *_test БД, восстановленную БД не трогать.

## Приёмка

## Результат

Добавлено optional поле через TypeSpec, API пересоздан и shared собран. Предоплата новой строки сохраняется атомарно с audit/receipt и учитывается в итогах; старую менять нельзя. Проверки: pnpm test (backend 354, frontend 235), pnpm test:int (82), backend typecheck и scoped lint, frontend lint/build. База тестов — costumes_test, Redis DB 15. Миграций нет.
