# T-083 · Возврат залога только после завершения визита

- **Приоритет:** medium
- **Область:** Баги домена
- **Создана:** 2026-10-18
- **Выполнена:** 2026-10-18

## Контекст

`VisitOrderService.MarkDepositReturned` проверяет лишь наличие Deposit. Сейчас endpoint может отметить залог возвращённым, когда визит ещё `reserved`/`issued` или когда тип залога `none`. По флоу возврата (`.agents/domain.md` §4.4) отдельная отметка доступна для завершённых визитов с реальным залогом. Повторный запрос сейчас идемпотентен; его поведение эта задача не меняет.

## Критерии готовности

- [x] `POST /visits/:id/mark-deposit-returned` принимает только `completed` визит с залогом `cash`/`document`.
- [x] Для других статусов и типа `none` возвращается понятная русская ошибка 400; несуществующий визит — 404.
- [x] Повторная отметка остаётся идемпотентной.
- [x] Unit и integration тесты покрывают допустимый и недопустимые сценарии; остальные сценарии возврата проходят.

## План

Добавить проверку статуса визита и типа залога до транзакции, сохранив идемпотентность. Покрыть unit-тестами статусы и оба реальных типа залога, integration-сценарием — состояние БД до и после завершения визита. Integration последовательно запускает ведущий агент из-за общей тестовой БД.

## Результат

Коммит: `2896f39`.

Добавлены русские ошибки 400 для незавершённого визита и `none` залога, 404 для отсутствующего визита. Unit-тесты добавлены; integration-сценарий в `test/visit-guards.int-spec.ts` и весь backend integration-набор прошли (33/33).
