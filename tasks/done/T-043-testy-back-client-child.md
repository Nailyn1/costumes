## Критерии готовности

- [x] Создание клиента: валидация имени (кириллица/латиница, ≥2) и телефона `+7XXXXXXXXXX` → 400; дубликат активного телефона отклоняется прикладной проверкой (уникального индекса БД нет, см. T-029).
- [x] Создание ребёнка у существующего клиента; несуществующий клиент → 404. Удалённый клиент — известный дефект T-080, отмечен `it.todo`.
- [x] Soft delete клиента и ребёнка: `deletedAt`, не попадают в поиск/список/detail; удаление клиента с активными визитами — зафиксировать текущее поведение. Повторные мутации удалённых записей — T-081.
- [x] Чёрный список: `POST /clients/:id/blacklist` с причиной ставит `isBlacklisted` и `blacklistReason`, `DELETE` снимает и очищает причину; повторная постановка; несуществующий клиент → 404; клиент из ЧС не может бронировать (integration: `POST /visits` → 400 с причиной), после снятия — может.
- [x] Поиск клиентов (`search`): имя / телефон (+7, часть номера), ранжирование, минимум 2 символа; в ответе дети и флаг ЧС; удалённые дети не возвращаются. Поиск через `8` — T-082, «Арина» vs «Марина» — T-034, оба отмечены `it.todo`.
- [x] `list` и `detail/:clientId`: пагинация, дети и история визитов без удалённых.
- [x] Backend unit и integration-наборы зелёные, typecheck и lint без ошибок.

## План

- Добавить unit-тесты `ClientChildService` на создание, soft delete, поиск/ранжирование, список/detail и чёрный список.
- Добавить отдельный integration-набор на HTTP-валидацию, soft delete и запрет бронирования клиента из ЧС.
- Известные баги и пробелы, которые нельзя исправлять в рамках тестовой задачи, отметить `it.todo` и передать владельцу для backlog.
