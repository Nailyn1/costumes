## Контекст

Найдено при T-048. В `clientModal.tsx` `handleAddBlacklist` вызывает `onClose()` сразу после `mutate(...)`, не дожидаясь ответа: карточка клиента закрывается, даже если запрос упал (404/500) — сотрудник видит только toast ошибки и не понимает, применён ли запрет. Кроме того, при пустой причине на сервер уходит `blacklistReason: ""` вместо отсутствующего поля. Поведение зафиксировано тестом (`ClientsPage.test.tsx`); причина в UI «необязательно» — вопрос «обязательна ли причина» ([T-048](../done/T-048-testy-front-klienty-chernyy-spisok.md)) решает владелец.

## Критерии готовности

- [x] Карточка закрывается/обновляется только после успешного ответа; при ошибке остаётся открытой.
- [x] Решение владельца (2026-10-18): причина необязательна; пустая причина не отправляется как `""`.
- [x] Тесты в `ClientsPage.test.tsx` обновлены.

## План

1. Закрывать карточку и окно причины лишь после успешного ответа мутации; при ошибке оставлять их открытыми.
2. Отправлять причину только после `trim()` и только если непустая.
3. Обновить тесты успеха, ошибки и необязательной причины; запустить frontend тесты, typecheck и lint.

## Результат

Карточка закрывается в `onSuccess` мутации; при 404 остаются открытыми и карточка, и окно причины. Причина обрезается по краям и при пустой строке поле не отправляется. Тесты проверяют оба исхода. Frontend: 118 passed / 1 todo, typecheck и lint без ошибок.
