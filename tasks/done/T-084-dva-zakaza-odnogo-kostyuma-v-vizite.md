# T-084 · Запретить два заказа одного костюма в одном визите

- **Приоритет:** high
- **Область:** Баги домена
- **Создана:** 2026-10-18
- **Выполнена:** 2026-10-18

## Контекст

`VisitOrderService.createVisit` передаёт все `costumeId` в `isSuitAvailability`, который ищет только уже сохранённые заказы. Если в одном новом запросе два заказа на один костюм, проверка не находит конфликта между ними и может создать оба. Это нарушает правило одного физического костюма на пересекающийся период (`.agents/domain.md` §3).

## Критерии готовности

- [x] `POST /visits` отклоняет два заказа одного костюма в одном запросе понятной русской ошибкой 400 до записи визита.
- [x] Корректные заказы на разные костюмы в одном визите проходят.
- [x] Unit и integration тесты доказывают отсутствие частично созданного визита при ошибке.

## План

Проверить дубли `costumeId` до чтения резерва и транзакции в `createVisit`. Добавить unit-тесты дубля и разных костюмов, отдельный integration-сценарий с проверкой отсутствия Visit и Order в БД. Запустить unit, typecheck, lint; integration последовательно запускает ведущий агент из-за общей тестовой БД.

## Результат

Дубли костюма отклоняются русской ошибкой 400 до записи. Unit-тесты добавлены; integration-сценарий в `test/visit-guards.int-spec.ts` и весь backend integration-набор прошли (33/33).
