Главный модуль, через него проходят деньги и костюмы (`apps/backend/src/visit-order/visit-order.sevice.ts`). После T-022, T-024, T-037, T-038, T-077 и T-079 уже есть тесты чёрного списка, soft delete, доступности после возврата и части выдачи/возврата. Стратегия, структура и образцы — [testing.md](../../.agents/testing.md). Бизнес-правила — [domain.md](../../.agents/domain.md). Известные баги не чиним вне их задач: отмечаем `it.todo` со ссылкой на актуальную задачу.

## Критерии готовности

- [x] **Бронь (`createVisit`):** `prepaymentAmount > rentPrice` → 400 (граница `=` проходит); `startDateTime > endDateTime` → 400; код визита без резерва в Redis → 409, после создания ключ `visit_code_lock:{code}` удаляется; склейка даты и времени в UTC «как есть» (`2026-12-20` + `18:30` → `2026-12-20T18:30:00Z`); `sendNotification=true` создаёт Notification `pending` и job `send-whatsapp` с `jobId=notification-{id}`, `false` — нет; сбой очереди не откатывает создание визита; ошибка `P2003` обрабатывается.
- [x] **Занятость (`isSuitAvailability`):** пересечение `start < otherEnd && end > otherStart` (границы: встык = свободно, перекрытие на минуту = занято); отменённые, удалённые и возвращённые заказы не блокируют (T-024 исправлена); два заказа с одним костюмом в одном запросе отклоняются (T-084).
- [x] **Генерация кода (`generatePreviewCode`):** 4 цифры, пропуск занятых в Redis и в БД, исчерпание попыток → 500, резерв с TTL 15 мин.
- [x] **Бирка (`orderMarkTagWritten`):** `not_written → written`; несуществующий/удалённый заказ → 404; список `findOrdersNotWritten` не содержит отменённых, возвращённых и заказов закрытых/отменённых визитов.
- [x] **Выдача (`visitIssue`):** выдать можно только `reserved` (остальные статусы — 400 с понятным текстом); все заказы и визит → `issued`; текущая раскладка доплаты по заказам покрыта тестом, учёт недоплаты/переплаты вынесен в T-028 (`it.todo`); Deposit создаётся (`cash` с суммой, `document`, `none`), `returned=false`; атомарность — при ошибке ничего не записано; `visit.notes` дописывается (T-087).
- [x] **Отмена выдачи (`visitUnissue`):** `issued → reserved`, заказы → `reserved`, `finalPayment` сбрасывается; не `issued` → 400; физическое удаление Deposit — известный баг T-026 (`it.todo`).
- [x] **Отмена визита (`visitCancel`):** только из `reserved`; заказы → `cancelled`; костюм снова доступен для новой брони (integration).
- [x] **Возврат (`visitCompleteReturn`):** только `issued`; заказы → `returned`, визит → `completed`; `depositReturned` ставит `Deposit.returned`; комментарий дописывается с префиксом `[Завершение]:`; залог не блокирует закрытие; частичный возврат невозможен (T-027, `it.todo`).
- [x] **Залог (`MarkDepositReturned`):** только для `completed` с `type≠none` (T-083); повторная отметка; комментарий.
- [x] **Выборки:** `visitReserved` (фильтр по датам, пагинация `{items,total,page,limit,hasMore}`), `visitsIssuedForReturn`, `visitSearch` / `visitsReturnSearch` (код, ребёнок, костюм, inventoryCode, телефон; минимум 2 символа), `visitsUnreturnedDeposits`; фильтры `deletedAt: null` уже покрыты T-038/T-077 — дополнять тесты только для непроверенных условий и ответов.
- [x] Integration (`apps/backend/test/`): сценарии «отмена → костюм снова свободен», «выдача → отмена выдачи → повторная выдача», «возврат с залогом cash → отметка залога», конфликт брони на пересекающиеся даты (базовый сценарий уже есть в `visit-flow.int-spec.ts`).
- [x] Эквивалентные локальные запуски unit и integration зелёные; typecheck и полный backend lint без ошибок (`pnpm` не запускается в среде из-за EPERM).
