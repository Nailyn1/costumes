# Как мы работаем

Проект ведёт **один разработчик** (владелец) вместе с AI-агентами. Других людей не будет: процесс лёгкий, но дисциплина — строгая, потому что `main` сразу уходит в прод, а в проде живые брони сезона.

## 1. Цикл задачи

1. **Задача берётся из [`tasks/`](../tasks/README.md).** Владелец переносит файл задачи из `tasks/backlog/` в `tasks/in-progress/`. Нет задачи — сначала создай файл в `backlog/` по шаблону (агент может предложить формулировку).
2. **Разобраться.** Прочитать затронутый код и нужные доки: [domain.md](./domain.md) — всегда при изменении бизнес-логики; [backend.md](./backend.md) / [frontend.md](./frontend.md) / [shared-api.md](./shared-api.md) — по области; [testing.md](./testing.md) — когда пишешь или правишь тесты.
3. **План.** Для задач больше пары файлов — короткий план (что меняем, в каких файлах, как проверим) до начала правок. Неясности в бизнес-правилах — **спросить владельца**, не угадывать.
4. **Ветка.** От актуального `main`: `<type>/<короткое-описание>`, напр. `fix/issue-only-reserved`, `feat/partial-return`, `chore/pnpm`.
5. **Реализация.** Порядок для фич с API: `shared` (TypeSpec → gen → export → build) → миграция Prisma (если нужна) → backend → frontend.
6. **Проверки** (Definition of Done, ниже).
7. **Ревью владельцем.** Агент **не коммитит**, пока владелец явно не попросил. Владелец смотрит дифф глазами.
8. **Коммит / merge в `main`** → автодеплой.
9. **Учёт.** Файл задачи переносится в `tasks/done/` (дата, критерии, результат); если поменялось поведение/правила — обновить `.agents/*` в том же изменении.

## 2. Правила для агента

- Не коммитить и не пушить без явной просьбы. Не делать force-push, не переписывать историю `main`.
- Никогда не коммитить `.env*` (кроме `apps/crm-frontend/.env.production`), сертификаты, дампы БД, `src/prisma/generated`, `dist`, `tsp-output`.
- Не редактировать применённые миграции. Деструктивные миграции — только с явного согласия владельца.
- Не менять API в обход `shared` (см. [shared-api.md](./shared-api.md)).
- Не «чинить» тест, подгоняя ожидание под сломанное поведение; не удалять и не отключать тесты без согласия владельца. Тесты работают только с `costumes_test` и Redis db 15 — не направлять их на dev/прод-БД.
- Известные баги из [domain.md §6](./domain.md#6-известные-проблемы-подтверждены-владельцем-как-багинедоработки) не чинить «заодно» — только в рамках своей задачи. Найденные новые проблемы — оформить задачей в `tasks/backlog/`, а не молча исправлять.
- Минимальный дифф: не переформатировать и не переименовывать файлы, не относящиеся к задаче.
- Тексты интерфейса и сообщения об ошибках — на русском; код, коммиты, имена веток — на английском.
- Документация в `.agents/` — на русском.

## 3. Definition of Done

Задача считается сделанной, когда:

- [ ] typecheck проходит: `shared` build, backend `tsc --noEmit`, frontend `tsc -b`;
- [ ] lint без новых ошибок в изменённых файлах (backend, frontend);
- [ ] **тесты проходят:** `pnpm test` (unit backend + frontend) и `pnpm test:int` (integration backend, если задача трогает backend); подробности — [testing.md](./testing.md);
- [ ] **новая бизнес-логика и баг-фиксы — с тестами:** новое правило → unit-тест сервиса (при сквозном влиянии — сценарий в integration); баг-фикс → тест, воспроизводящий баг (красный на старом коде); frontend-логика (расчёты, формы, хуки) → vitest;
- [ ] миграция (если есть) создана через `prisma migrate dev` и её SQL просмотрен;
- [ ] UI проверен вручную в браузере: десктоп + мобильная ширина (375px);
- [ ] сценарий проверен end-to-end на локальной БД (бронь → бирка → выдача → возврат, если задача их касается);
- [ ] `.agents/*` обновлены, если изменились правила, флоу или схема.

## 4. Коммиты

[Conventional Commits](https://www.conventionalcommits.org/), на английском: `<type>(<scope>): <summary>`.

- **type:** `feat`, `fix`, `refactor`, `chore`, `docs`, `test`, `style`.
- **scope:** `front`, `back`, `shared`, `root`, `infra`.
- Примеры:
  - `fix(back): allow issuing only reserved visits`
  - `feat(shared): add partial return contract`
  - `chore(root): migrate to pnpm workspaces`
  - `docs(root): describe agent workflow`
- Изменение, затрагивающее shared + back + front одной фичей, можно одним коммитом со scope основной части или разбить по scope.

## 5. Деплой и прод

- Push/merge в `main` → GitHub Actions собирает образы → сервер делает `git pull`, `compose pull/up`, `prisma migrate deploy`. Подробнее — [architecture.md §4](./architecture.md#4-инфраструктура-и-деплой).
- Перед merge изменений со схемой БД — убедиться, что миграция совместима с данными прошлого сезона.
- Вне сезона сервер выключен; бэкапы не работают ([T-012](../tasks/backlog/T-012-bekapy-bd-v-s3.md)).
- Сезонное окно: всё крупное (мажорные обновления, переделки схемы) — **до** начала новогоднего сезона; во время сезона — только багфиксы.
