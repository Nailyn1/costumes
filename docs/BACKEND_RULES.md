# Backend Development Rules

## 1. Architecture & Layers (NestJS)

- **Strict Layering:** Приложение построено на фреймворке **NestJS** и разделено на Controllers (роутинг и HTTP) и Services (бизнес-логика и работа с БД). Отдельного слоя Data Access (репозиториев) НЕТ.
- **Controllers:** НИКАКОЙ бизнес-логики в контроллерах. Они только принимают запрос, вызывают нужный Service и возвращают ответ.
- **Services:** Вся бизнес-логика (расчет стоимости аренды, проверка доступности костюма), а также **прямые обращения к базе данных** через Prisma Client должны находиться исключительно в сервисах (`@Injectable()`).

## 2. API & Validation (CRITICAL)

- **Shared Types:** ВСЕ типы Request/Response DTO импортируются ИСКЛЮЧИТЕЛЬНО из пакета `shared/dist`.
- **Validation:** Входящие данные (body, query, params) ВСЕГДА валидируются с помощью Zod-схем, импортированных из `shared`. Запрещено писать локальные интерфейсы для API.
- **Errors:** Никогда не возвращай сырые ошибки базы данных на клиент. Перехватывай их и возвращай стандартизированные HTTP-ответы (400 Bad Request, 404 Not Found, 409 Conflict).

## 3. Database & Prisma

- **No Raw SQL:** Всегда используй Prisma Client (например, `this.prisma.client.findMany`). Использовать сырые SQL-запросы (`$queryRaw`) разрешено ТОЛЬКО для сложных аналитических запросов, если Prisma не справляется.
- **Transactions:** Если операция изменяет несколько таблиц (например, создание Визита и обновление статуса Костюма), ОБЯЗАТЕЛЬНО используй транзакции `prisma.$transaction`.
- **Soft Deletes:** Мы не удаляем сущности физически (особенно клиентов и заказы). Удаление происходит ТОЛЬКО через заполнение поля `deletedAt` датой удаления.
  **ВНИМАНИЕ:** При любых выборках данных (`findMany`, `findFirst`, `findUnique` и т.д.) всегда не забывай добавлять фильтр `where: { deletedAt: null }`, чтобы удаленные записи не попадали в результат.

## 4. Redis Caching & Sessions

- **Key Naming:** Все ключи Redis должны иметь префикс, связанный с доменом, например: `costumes_crm:session:{userId}` или `costumes_crm:cache:costume_catalog`.
- **TTL:** При записи в Redis всегда устанавливай время жизни ключа (EX), чтобы избежать переполнения памяти.

## 5. TypeScript Rules

- Запрещено использовать `any`. Если тип неизвестен, используй `unknown` и пиши type guard.
- Избегай мутаций переменных. Предпочитай `const` и функциональные методы массивов (`.map`, `.filter`).
